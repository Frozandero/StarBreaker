# default_value_registry_v1.json — provenance notes

Companion to `default_value_registry_v1.json` (JSON carries no comments).
One section per pinned path family: what it is, where the value came from,
and the sunset condition (usually "move to derivation in
`crates/starbreaker-3d/src/ui_pipeline/ship_values.rs`"). Update this file
in the SAME commit as any registry change
(crates/starbreaker-ui/docs/ui-process-improvements.md item 10). Per-ship derived values do NOT
appear in the registry — they flow through
`PipelineInputs::derived_values` at export/replay and shadow these paths
(probe with `SB_SHIP_VALUES_DUMP=1`).

| `FlightController/AccelerationLimiterRatio` = 1.0 | At-rest acceleration-limiter ratio for the g-force / velocity ball HUD (`adv_hud_g_ball`). The gauge gates `base_LIMIT Text`'s `IsActive` on `(AccelerationLimiterRatio < 1.0)` and shows the ratio as a `%`; at rest the limiter is NOT engaged (ratio = 1.0 = 100%), so the LIMIT readout is HIDDEN — matching `g_force_ball_master.png`, which shows no limit number at rest. Absent, the binding resolved to 0 → `0 < 1.0` true → a spurious "0%" LIMIT readout on the ball. Reference-verified (owner: the g-force amount does not show at rest) | Derive from the flight-controller limiter state once that telemetry is decoded |
| `flightController.forwardVelocity` = 0.0, `FlightController/ForwardBackSpeedGoal` = 0.0, `flightcontroller.totalgforceamount` = 0.0 | At-rest flight telemetry for the velocity-num HUD (`HC_HUD_Ship_Velocity_Num_Master`, DRAK cutlass variant). The readout binds `forwardVelocity` → `LocalizedSIUnitFromNumber("Speed")` and `totalgforceamount` → `Round` → `SIUnit` → `Combine("@hud_Symbol_Gees")`. Absent, both `NumberVariable`s resolve to `None`, so velocity falls to its `@ui_MFD_symbol_separator` placeholder (`-`) and the g-force combine drops the number (renders bare `G`). At static rest the ship is stationary: forward velocity 0, throttle goal 0, total g-force 0 — matching `ship_velocity_num_master.png` (`0m/s` / `0.0 G`). Same precedent as `AccelerationLimiterRatio` above (at-rest HUD telemetry, freeze-guarded). Path keys keep the authored separators (registry lookup is case-insensitive, leading-`/`-trimmed, dot/slash preserved) | Derive from the flight-controller telemetry once decoded |
| `FlightController/Compass/Ticks` = 0 (FALLBACK; derivation overrides it) | Compass HUD (`HC_HUD_Ship_Compass_Master`) tick array. `list_Ticks` binds `arrayVariable: "FlightController/Compass/Ticks"`; the engine pushes one entry per visible heading tick (`anchor` / `maintick` / `value`). This static `0` is now only the FALLBACK for vehicles whose HUD params don't resolve — it keeps the list empty (the lone authored `base_Tick` is a per-entry CLONE template; absent a count the list was skipped and it rendered as a stray left-edge tick). For vehicles with HUD params, `ship_values.rs::derive_compass_ticks` OVERRIDES this with the real at-rest tick set, derived from `SVehicleHudParams.VehicleHudDefault.compassTape` (`range`/`mainTickIncrement`/`subTicks` = 90°/20°/4 → minor every 5°) at the neutral heading 0° — emitting the count here plus `…/Ticks/[000j]/{anchor,maintick,value}`. Resolved via the multi-segment engine-state-path branch in `apply_array_variable_lists` (a bare list name still needs a namespace). The live in-flight heading (the ref's `100/120/140/160`) is unreproducible statically; heading 0 (North, like the velocity/g-force = 0 pins) is the principled at-rest value | Keep as the empty fallback; the derivation is the live path |
| `controllablemanager/mastermode` = 2 | At-rest master mode for the master-mode display (`HC_HUD_Ship_Master_Mode_Display_Master`, DRAK cutlass variant). `text_CurrentMode` binds `mastermode` → `LocalizationFromIntegerSwitch` (`2`→`@dfm_ui_ifcsSCM`="SCM", `1`→`@hud_nav`="NAV"). Absent, it falls to `@LOC_EMPTY` and the mode line is blank. A powered, flight-ready ship defaults to SCM (Standard Combat Mode) — value 2 — matching `master_mode_display_master.png` which reads "SCM". Same precedent as the velocity/g-force/compass at-rest telemetry pins. | Derive from the controllable-manager master-mode state once that telemetry is decoded |
| `seatdashboard/currentmode` = 3 | At-rest seat-dashboard operator mode for the master-mode display. Drives BOTH the submode line (`text_SubMode` ← `ParamInput1` ← `LocalizationFromIntegerSwitch`: `3`→`@hud_op_Combat`, localising to "GUN") AND the weapon-group icon (`shape_Icon.SvgPath` ← `ParamInput4` ← `StringFromIntegerSwitch`: `3`→`guns.svg`). A powered, weapons-ready ship in SCM defaults to the Combat operator mode (weapons/shields on) — value 3 — matching `master_mode_display_master.png` which shows 4 bullets + "GUN". The ARC-1 note that this was "live combat state with no principled at-rest value" was overturned: weapons-on IS the power-on default (owner-confirmed), the same principle as `mastermode`=2 SCM. Could be stored as a generic default for all ships. | Derive from the seat-dashboard operator-mode state once that telemetry is decoded |
